# 実用版 v1 — 「束で載せて、1回ずつは手元で数える」

2026-11-16 仕様。v0.4（docs/AUTHORITY_UTXO.md）の弱点「1回ごとに K ブロック待つ」を、チェーンに載せる操作を減らして解く。

## 一行で

**チェーンは「回数券の束」の発行・委任・預け入れ・没収だけに使う。1回ずつの呼び出しは、サービス前のゲートウェイがミリ秒で数える。**

## 役割

| 役 | 何をする |
|---|---|
| 発行者（会社A） | 束（例: 1000回・操作範囲P・期限T）を権限UTXOとして発行 |
| 委任者（会社B のAI など） | 束を分けて下へ委任（既存の covenant） |
| 利用者（末端のAI） | 束をサービスへ「預け入れ」、以後は署名つき HTTP で呼ぶ |
| ゲートウェイ（サービス側） | 預かった束の残数を数え、範囲・期限・署名・再送を検査して API へ通す |
| 祖先 | 自分より下の束をいつでも止める（即時）、残りを取り戻す（チェーン） |

## チェーンに載る操作（まれ）

1. **発行・委任** — v0.4 のまま。
2. **預け入れ（bind）** — 利用者が束をゲートウェイの鍵へ委任する（holder＝ゲートウェイ鍵）。預け先が1つに決まるので、同じ束を2つのサービスで使う二重使用はチェーンが止める。待ちは束の価値で決める K（小さい束は K=0〜1）。
3. **精算（settle）** — ゲートウェイが使った回数 k をまとめて消費する。covenant の使用パスを「1減らす」から「k 減らす（1≤k≤n）」に一般化。残りは同じ型で残り、祖先が回収できる。
4. **没収（reclaim）** — v0.4 のまま。預け入れ後でも祖先は奪還できる。

## 手元（毎回・ミリ秒）

- 呼び出しは `X-Tranche: <txid:vout>`、`X-Agent-Key`、`X-Nonce`、`X-Agent-Sig`（メソッド・パス・本文ハッシュ・nonce・束IDへの署名）。
- ゲートウェイは、(a) 署名が預け入れ時に開示された祖先列の末尾鍵（＝預けた利用者）か、(b) 操作が P のビットに入るか、(c) 期限 T 内か、(d) nonce 未使用か、(e) 残数 > 0 か、を検査し、残数を原子的に1減らして通す。保存は Node 標準の `node:sqlite`。
- **即時停止:** 祖先列のどの鍵でも、署名つき停止要求をゲートウェイへ送れば、その束は即座に止まる（チェーン待ちなし）。兄弟の束は止まらない。
- **チェーン監視:** 預け入れ UTXO がゲートウェイ以外に消費された（＝祖先の奪還）ら、その束を止める。

## 何を信頼するか（正直に）

- ゲートウェイは「使った回数」を正しく数え、精算で正しい k を書くと信頼する。ゲートウェイは API を実際に動かす当事者なので、ここは元々信頼されている。
- チェーンが守るのは、束の総数・範囲・期限・委任の木・預け先の一意性・祖先の没収権。ゲートウェイは束を水増しできない（精算は k 減らすだけ）。
- 精算前に祖先が奪還すると、手元で使った回数ぶんを祖先が多く取り戻せる。ゲートウェイは署名つき利用記録で争える（v1 は記録だけ残し、自動の争議は扱わない）。

## 受入条件

1. `npm test` 緑。covenant の USE_K（k=1, k=n, k=0拒否, k>n拒否, k で P/T 拡大拒否）を Spend.validate で検証。
2. ゲートウェイ: 正しい署名で通る／別鍵・範囲外・期限切れ・nonce 再送・残数0・停止後は拒否。並行100呼び出しで残数が負にならず、合計がちょうど n。
3. 即時停止: 祖先鍵の停止要求で1枝だけ止まり、兄弟の束は通り続ける。祖先列外の鍵の停止要求は拒否。
4. デモ `npm run demo`: 会社A→B→Bの子AI2体、モックAPI。1回あたりの判定時間 p50/p99 を表示（目標 p99 < 5ms、チェーン待ちなし）。途中で片方の子を停止し、もう片方が続くことを表示。チェーンはメモリ上のアダプタ（regtest アダプタは任意）。
5. 実資金・メインネット送信・外部送信なし。
