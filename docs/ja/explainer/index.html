AIに渡した「回数券」を、
1体だけその場で止められる仕組み

AIが仕事をどんどん別のAIに任せる時代に、「暴走した1体だけを止めて、他は止めない」を実現する。ユースケースで順に見ていきます。

AIに渡す権限を「回数券の束」にする。束は分けて渡せるが、枚数は増やせない。
そして上の人は、自分の下の1体だけを、いつでも止められる。

登場人物

架空の例です。AI運用代行の「ミライ運用社」が、通販会社の問い合わせ対応をAIで回しています。

🏢
通販会社（発注元）検索APIの利用枠「1,000回」を、ミライ運用社に渡す
🧑‍💼
ミライ運用社のリーダーAI受け取った枠を、部下のAIたちに分けて渡す
🤖
部下AI・外注先のAI調査AI・返信下書きAI・外注先（別会社）のAI

ユースケース①　いつもの流れ — 枠を分けて、使う

リーダーAIは1,000回を「調査AIに400」「下書きAIに400」「外注先に200」と分けて渡します。分けた合計は元の1,000を超えられません。子は親より広い操作もできません（例：「検索だけ」の枠から「メール送信」は生まれない）。

1回ごとの確認は、サービス入口（ゲートウェイ）が手元で行います。実測で1回 1ミリ秒未満（p99 0.6〜0.9ms）。AIは待たされません。

ユースケース②　1体が暴走 — その1体だけ止める

  1. 調査AIが、怪しいWebページの指示に乗っ取られる。検索APIを猛烈な勢いで叩き始める。
  2. リーダーAI（または人）が「調査AIを止める」に署名して入口へ送る。チェーンの確定は待たない。ミリ秒で効く。
  3. 調査AIの次の呼び出しは拒否（403）。下書きAIと外注先は、何事もなく動き続ける。
  4. 調査AIが使い切らなかった残りは、リーダーへ戻る。使った分と残りが二重に数えられることはない。

↑ 上のデモで「乗っ取られた」→「調査AIだけ止める」→「残りを回収」を押すと、この流れを見られます。

ユースケース③　別会社への再委任 — 外注先のAIも同じルール

いままで

外注先にAPIキーをそのまま渡す。外注先がさらに別のAIへ渡しても、こちらからは見えない。止めるにはキーごと無効化 → 自社の他のAIも全部止まる。

この仕組み

外注先には「200回・検索だけ・今月末まで」の束を渡す。外注先がさらに分けても合計200を超えない。問題が出たら外注先の枝だけ止めて、残りを回収。

従来のやり方と比べると

やりたいことAPIキーを共有キーを人数分発行この仕組み
暴走した1体だけ止める全員止まるできるできる（ミリ秒）
AIがさらに別のAIへ分けて渡す追えない発行者が毎回発行AI自身が分けられる
分けても合計が増えない保証なし中央の管理画面しだい構造的に保証
止めた分の残りを回収—手作業自動で戻る
1回あたりの速さ速い速い1ms未満

正直に言うと、1社の中だけなら「キーを人数分発行＋管理画面」でもかなりのことはできます。差が出るのは、AIが何段も仕事を任せ合い、会社をまたぐときです。

ブロックチェーン（BSV）はどこで効くのか

製品はチェーンなしで動きます。入口（ゲートウェイ）が回数を数え、束の記録は普通のデータベースに置きます。

BSV は「差し替えられる部品」として載っています。束の発行・委任・預け入れ・没収をBSVに記録すると、どの会社のデータベースも信用しなくても「合計が増えていない」「上の人が没収できる」を、ルール（スクリプト）として誰でも確かめられます。

これは研究として本物のBSVノード（regtest）で動作確認済み。ただし、チェーンが絶対に必要なお客さんは今のところ見つかっていません。

まだできていないこと（正直に）

  • 入口（ゲートウェイ）が正直に数えることは信頼している。入口そのものの不正は防げない。
  • 止める前に入口が通してしまった呼び出しは取り消せない（「次の呼び出しから」止まる）。
  • 実際の顧客での試用、第三者のレビューはまだ。
